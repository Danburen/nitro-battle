# B 模式设计方案：迷雾探索（文明 / 群星式）

> 状态：设计稿，暂缓实现。A 模式（全图归属、无中立）已上线，本文档描述与之并行的第二种开局模式。
> 关联代码：`src/game/generator/*`、`src/game/diplomacy.ts`、`src/game/settlement.ts`、`src/render/renderer.ts`、`src/ui/panels/diplomacy.ts`。

## 1. 模式定位

| 维度 | A 模式（现行） | B 模式（本方案） |
| --- | --- | --- |
| 开局领土 | 全图陆地按州均衡归属各 AI 国家 | 玩家仅 1 个州；其余陆地为中立 |
| 中立地区 | 不存在（水域除外） | 大量存在，无驻军 |
| 视野 | 全图可见 | 战争迷雾：未知区域统一灰色阴影 |
| 扩张 | 宣称 → 战争借口 → 宣战夺取 | 对中立州直接宣称，花费时间完成整合 |
| 外交 | 开局即与所有国家存在关系 | 接触到 AI 国家后才建立外交关系 |
| 接触后 | — | 双方共享视野，规则收敛到 A 模式 |

两种模式共用同一套战斗、经济、建造、结算规则；差异集中在**生成、视野、宣称流程、外交建立时机**四处。

## 2. 开局生成

- 新增设置项 `mode: "a" | "b"`（`GameSettings`），默认 `"a"`，新战役面板提供选择。
- B 模式生成流程：
  1. 地形 / 州划分与 A 模式完全一致（复用 `generator/terrain.ts`、`generator/states.ts`）。
  2. 玩家首都州：按 A 模式规则选一个州作为玩家唯一领土（首都 + 初始建筑 + 初始军团与 A 模式相同）。
  3. 其余全部陆地州 `owner = legalOwner = coreNation = NEUTRAL`，`occupation = 0`，`garrison = 0`。
     - `NEUTRAL` 哨兵已在代码中保留（水域、系统日志、关系色调），B 模式直接复用，无需新增常量。
     - `rules.ts` 的 `isHostileProvince` 对 NEUTRAL 返回 false，中立州不可被攻击，只能宣称整合。
  4. AI 国家同样各只拥有 1 个首都州，彼此分散布置（沿用 A 模式的 capitals 选址，但不再做领土均衡分配）。
  5. 中立州保留 `factories / infrastructure / buildings` 的生成值，整合后直接继承，形成探索收益差异。
- 名称生成、确定性种子复现等约束与 A 模式一致。

## 3. 战争迷雾与视野模型

### 3.1 数据

```ts
interface Vision {
    /** 每个州对每个国家的可见等级：0 未知 / 1 已知（曾见或邻接已知）/ 2 实时可见 */
    level: Uint8Array; // states.length * nations.length
}
state.vision: Vision | null; // A 模式为 null，渲染与 UI 走全图分支
```

- 视野按**州**粒度计算（用户要求：只显示已知 state 和周围的 state）。
- 实时可见（2）：本国领土州 + 本国军团所在州 + 这些州的邻接州。
- 已知（1）：曾经实时可见、或当前与任一实时可见州邻接的州。已知州显示**上一次看到时的快照**（归属、驻军概况），不保证实时。
- 未知（0）：统一灰色阴影覆盖，不渲染州名、建筑、军团；小地图同样灰化。
- 每回合结束重算一次 `level`（回合制，无逐帧开销）；州归属变化事件触发增量更新。

### 3.2 渲染

- `renderer.ts` 新增迷雾层：未知州填充中性灰（取自现有 `--site-bg` 系中性色，加细噪点纹理避免死板），已知但非实时州叠加半透明暗色纱罩。
- 迷雾层绘制在 base canvas 之上、军团 counter 之下；未知州的 counter / 标签 / 宣称高亮全部跳过。
- 州模式 hover：未知州不触发聚合快照；已知州显示快照并注明「情报可能过时」。
- 宣称面板与外交 tab 只列出**已建立关系**的国家；未知 AI 国家不出现在 tab 卡中。

### 3.3 快照

- `state.intel: Map<stateId, { owner, day, garrisonApprox }>` 记录每个已知州最后一次实时观察的数据，供已知州 tooltip 与小地图着色使用。

## 4. 中立扩张：计时宣称

- 对中立州发起宣称复用 `claimState`（政治点成本沿用 `CLAIM_COST = 8`），但进入**整合计时**而非战争借口流程：
  ```ts
  interface Claim { nation: number; stateId: number; startedDay: number; readyDay: number; }
  ```
  现有 `claims` 数组扩展可选 `readyDay`；A 模式宣称不带该字段，行为不变。
- 整合时长建议 `3 + 州内省份数`（回合），受基础设施等级小幅减免；UI 在宣称面板显示进度条。
- `readyDay` 到达且该州仍为中立 → 自动完成整合：`owner = legalOwner = nation`，`occupation = 100`，`coreNation` 保持 NEUTRAL（非核心，沿用 A 模式占领区规则），驻军按上限的一定比例自动生成。
- 计时期间该州被他人抢先整合或变为非中立 → 宣称作废，政治点不退还（与 A 模式「授权取消」日志口径一致）。
- 中立州无驻军、不可攻击：`canClaimState` 已排除 NEUTRAL 作为**宣战目标**，B 模式需要新增「中立整合」分支（`canIntegrateState`），与战争宣称互斥：同一州同一时间只允许一个整合计时。
- 玩家与 AI 遵守相同规则；AI 的 B 模式扩张策略见 §6。

## 5. 接触与外交建立

- **接触判定**：任一国家的实时可见州与另一国的领土州邻接（含军团进入邻接州），即视为接触。
- 接触发生时：
  1. 建立外交关系：`state.war` 矩阵中双方初始为和平（沿用现有矩阵，无需新结构）；外交 tab 出现对方国家卡片。
  2. **双方共享视野**：两国 `vision.level` 互相合并为「对方实时可见即己方实时可见」，等效于 A 模式的全图可见子集；此后双方之间的情报不再有过时快照。
  3. 日志与 feed 提示「与 [国家 chip] 建立外交关系，视野共享」。
- 接触后对彼此的行为完全走 A 模式规则：宣称 → 战争借口（conquest / annex）→ 宣战 → 省份级争夺 → 结算。中立整合计时只适用于仍为中立的州。
- 未接触国家之间互不可见、互不宣战（`canDeclareWar` 增加「已建立关系」前置检查，A 模式视为全部已建立）。
- 第三方接触链不传递共享：A 与 B 共享、B 与 C 共享，不意味着 A 与 C 共享（避免视野瞬间全图化）。

## 6. AI 适配

- `runAIDiplomacy` / `prepareAIExpansion` 增加 B 模式分支：
  - 优先整合邻接中立州（政治点足够时发起计时宣称），扩张方向偏好高工厂 / 高基础设施州。
  - 与已接触国家的互动沿用 A 模式逻辑（宣称、借口、宣战、议和）。
  - AI 视野与玩家同规则计算，不允许读全图状态做决策（决策函数只接收可见州集合）。
- 难度差异通过整合时长修正与政治点收入修正表达，不开放作弊视野。

## 7. UI 变更清单

- 新战役面板：模式选择（A 全图争锋 / B 迷雾探索），附一句话说明。
- 外交页：tab 卡只含已接触国家；未接触时显示「尚未发现其他文明」空态与探索引导。
- 宣称面板：中立整合条目显示倒计时进度；已接触国家的战争宣称条目与 A 模式一致。
- 州 hover 聚合快照：B 模式已知州追加「情报日期：第 N 天」行；未知州无 tooltip。
- 小地图：未知区域灰色；实时 / 已知 / 未知三档图例。
- 手册 `guide.ts`：B 模式独立章节（迷雾、整合、接触、共享视野）。

## 8. 测试计划（实现时）

- 生成：B 模式开局仅玩家与 AI 各 1 州，其余陆地全部 NEUTRAL 且 garrison=0；种子复现。
- 视野：未知州不可 hover / 不可宣称 / 小地图灰化；邻接已知州自动升级；回合重算幂等。
- 整合：计时到期自动归属；抢先整合使对方宣称作废；政治点不足不可发起；同一州互斥。
- 接触：邻接即建交 + 视野合并；未接触不可宣战；共享不传递。
- 收敛：接触后战争流程与 A 模式回归用例（settlement / diplomacy）行为一致。
- 渲染：迷雾层不泄漏未知州 counter / 标签；A 模式（vision=null）渲染路径零变化。

## 9. 实施顺序建议

1. `GameSettings.mode` + B 模式生成（含回归）。
2. 视野数据与回合重算 + 渲染迷雾层。
3. 中立整合计时（claims 扩展 + advanceDiplomacy 分支）。
4. 接触判定、建交与视野共享。
5. AI B 模式分支、UI 与手册、全量 QA 与发布。

每步独立可验证，A 模式全程不受影响（vision=null、claims 无 readyDay 时走原路径）。
